## 論点A: v1 の精度・速度は記事/README と乖離していないか

- **速度: 乖離なし（賛成、確度高）**。E4 の生値 2643 秒は `--warmup-runs 0`・
  condition-cache 無し・カーネルキャッシュ毎回破棄の照合専用プロトコルで、
  DLS-005/007 の「プロトコル不一致値は無効値」がそのまま適用される。
  比較可能な唯一の指標 = サンプリング定常値は E4 1.13〜1.15 s/it vs 本線帯
  1.128〜1.175 s/it で同帯。v1/v2 は構造同一（config 差は `_diffusers_version` のみ）
  で速度差が生じる機構が無い。decode 1707 秒は torch.compile コールド autotune 支配
- **精度: 記事との乖離（19 倍）は E4 の主結果として確定済み**（DLS-014）。
  README は精度値を一切主張していないため「README との乖離」は定義上生じない
- 留保: 「乖離なし」判定は E4 の 1 run のみ。ただし v1 を速度比較に使う計画が
  存在しないため warm 測定の実益なし（反対しきれない、なぜなら用途が無いから）

## 論点B: v1/v2 の精度は許容範囲内か

- v1 の許容性議論は実益なし（golden からより遠く、照合実験専用）。実質論点は v2
- 「低い ≠ 使えない」に**賛成寄り留保付き**。根拠:
  1. 基準 0.05 は宣言のみで誰も執行していない（読むコードが存在しない）
  2. v2 の 0.126 は「不合格」というより世界唯一の実測
  3. 誤差の 40% はグリッパー dim9 の開閉タイミング 2 step 差で、閉ループ運用では
     致命傷とは限らない
- 留保: 「使える」側の実証もゼロ（タスク成功率・定性比較とも未実施）。
  許容判定は下流タスクを決めない限り原理的に閉じない
- **反対視点（併置）**: 記事は golden PASS の出力、本環境は FAIL の出力であり、
  「同一条件での速度比較」が出力別物同士の比較である疑い（DLS-011 の DLS-006 への
  留保）は残る。「許容」で先に閉じると帰属問題（本環境固有か公開資産の問題か）を
  曖昧にする。許容性の議論と帰属の議論は別物として保つ
- **「何もしない」候補**: 許容/不許容の判定自体を保留し CUDA 参照 run 決着後に
  README 表現と一括判断（= 当時の現行路線）

## ユーザー決定（本議論の確定事項）

1. **CUDA 参照 run は当分実施不可**の前提に変更
2. **精度は素の実測提示に凍結**（帰属決着手段が無い以上、実測数字以上を書かない）
3. **合否軸を「対記事倍率が価格差以内か」に変更**。当初レンジ 1.5〜2 の議論を経て
   **2.0 に確定**。「今時点では収まらない結論でも良い。それをベースにチューニングを
   進めていく」
4. **guidance 公式デフォルト実測を速度・精度とも実施** → 実行結果は DLS-016 /
   `20260728_doc_guidance_official_measurement.md`

## 基準確定の決め手になった算術（Policy）

41.66 秒の内訳はサンプリング 33.84 + デコード 7.49 + その他 0.33。サンプリングは
1.128 s/it × 30 step でメモリ帯域の物理限界（1.127 s/step、final report / DLS-001
再調査でも不変）に張り付いており、**デコードをゼロにしても 33.84 秒 = 1.61 倍**。
同一計算内容の制約（DLS-003）の下で 1.5 倍は算術的に不可能、現実的着地帯は
1.7〜1.9 倍。つまり基準が 1.5 なら本線チューニングは dead end、2.0 なら達成圏 —
この構造が「価格差をどこに固定するか」を最初に決めるべき理由だった。

価格差の一次出典は未固定のまま（DGX Spark $3,999 は堅いが、本環境側は機種・構成で
1.6〜2.4 に振れる）。ユーザーが基準値 2.0 を直接決定したため、価格の出典固定は
不要になった（将来対外文書に価格を書くなら要出典、DLS-006 教訓）。
