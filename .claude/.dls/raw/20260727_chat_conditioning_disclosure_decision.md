# conditioning 削減を対外文書にどう反映するかの決定

日付: 2026-07-27
種別: chat（議論ログ）
関連 DLS: DLS-009（本体）、DLS-006（assumption への依存低下）、DLS-008、DLS-003

---

## 1. 出発点

`--policy-min-condition-encode`（DLS-008）の E2E 検証と等価性実証が完了した
（`.claude/.dls/raw/20260727_doc_mincond_e2e_verification_and_nondeterminism_floor.md`）。

- `generate_batch` 124.906 → 42.438 秒
- conditioning（`get_data_and_condition`）81.575 → 0.276 秒
- 削減は近似ではなく厳密（サンプリングへの入力テンソル `initial_noise` がビット完全一致）

残る論点は「対外文書（README §2 / `docs/cosmos3_rocm_policy_optimization_final_report.md`）に
参考値として載せている『conditioning 込み 124.91 秒』をどう扱うか」。
DLS-006 でユーザー判断により整理した数値であり、対外主張に関わるため CC 単独では決めない。

## 2. 中立的再評価（3 案）

### 案 A: 42.44 秒に更新し、削減の根拠を注記する

- 対記事比は 5.95 倍 → **2.02 倍**
- DLS-006 の「生成のみ 41.66 秒 = 1.98 倍」とほぼ同値になり、
  「conditioning を含めても含めなくても対記事約 2 倍」という一貫した説明ができる
- 注記で「推論結果に到達しない 16 フレーム分を除去した」「除去は厳密でサンプリング入力が
  ビット一致する」ことを示す

### 案 B: 124.91 秒を残し 42.44 秒を併記する

- 履歴の追跡性は最も高い
- 弱点: DLS-006 で整理したばかりの表がまた複雑になる。読者にどちらが現在値か伝わりにくい

### 案 C: 何もしない（124.91 秒を維持）

**これが反対視点。形だけの反対ではなく、実質的な論拠がある:**

- `--policy-min-condition-encode` は **既定オフの実験フラグ**。
  既定設定で動かしたときの実測値は 124.91 秒のままである
- フラグ前提の数値を公表値に据えるのは「条件の後付け」にあたり、
  DLS-005（`--policy-condition-cache` 必須という再現条件が repo に無く誤報を生んだ）や
  DLS-006（基準値 29.00 秒に一次出典が無かった）で問題になった構造と同型になりうる

## 3. 確定事項

**案 A を採用**（ユーザー選択、2026-07-27）。

採用理由:

1. 削減が近似ではなく**厳密**であることを実測で示せる。したがって 124.91 秒は
   「無駄な計算を含んだ測定値」と位置づけられ、それを公表値の主にする方が実態から遠い
2. 案 C の懸念（条件の後付け）には、記載側で対処する:
   - README の表に `--policy-min-condition-encode` 適用時と明記する
   - 未適用時の 81.57 秒も併記する
   - 削減フラグ無しの 124.91 秒の再現手順も残す
   これにより「どの条件の数値か」が文書上で自己完結する（DLS-005 の教訓の適用）
3. 案 B の併記案は、DLS-006 で単純化したばかりの表を再び複雑にするため採らない。
   ただし上記 2 の措置により、案 B が守ろうとした追跡性は実質的に確保される

## 4. 副次的効果: DLS-006 の assumption への依存が消えた

DLS-006 は「記事の『モデル常駐後 21 秒』は入力観測エンコードを含まない生成のみの値である」を
confidence: medium-high の assumption として置き、その根拠の一つが
「conditioning 単体 81.57 秒 > 記事の総時間 21 秒」だった。

conditioning が 0.28 秒になったことで、この論法は使えなくなる。しかし同時に
**assumption そのものへの依存が消える**:

- 記事が conditioning を含まない場合 → 本環境 41.66 秒（1.98 倍）
- 記事が conditioning を含む場合 → 本環境 42.44 秒（2.02 倍）

どちらでも結論が変わらない。推定が外れても対外主張が揺らがない状態になった。
これは案 A を選ぶ積極的な理由でもある（案 C のままだと 124.91 秒 = 5.95 倍と
41.66 秒 = 1.98 倍が併存し、assumption の当否で見え方が大きく変わる状態が続く）。

README / 最終報告の該当箇所も、この趣旨に書き換えた。

## 5. 議論再開時の起点

- 記事側の内訳（前処理 / サンプリング / デコード）が判明した場合。
  DLS-006 の assumption を確定または棄却でき、§4 の整理も見直す
- `--policy-min-condition-encode` を既定オンにするか検討する場合。
  現在は安全弁（`condition_frame_indexes_vision == [0]` のときのみ適用）付きの
  オプトイン。既定オン化は runner の挙動変更にあたり、別途判断が要る
- 削減対象が policy 以外のモード（T2I / T2V / I2V）にも存在するか未調査
