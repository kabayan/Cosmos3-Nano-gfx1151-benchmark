# Skill 06 — todo.md 衛生管理

`tasks/todo.md` を「現時点で active なタスク + マスターへのリンク情報のみ」に保つ。
完了タスクと、コード／DLS／外部ドキュメントに既に存在する情報の重複は許さない。

---

## 原則

1. **todo.md は揮発ワーキングメモリ**: 完了タスクは残さない。コミット履歴と DLS が永続記録の役割を担う
2. **DRY**: 同じ情報を 2 箇所以上で保持しない
   - コード本体に存在する事実は再記述しない（`path:line` で参照）
   - DLS 判断ログに存在する判断理由は再記述しない（`DLS-XXX` で参照）
   - コミットメッセージで完結する変更内容は todo.md から削除する
3. **マスターへのリンクのみ残す**:
   - ファイル: `path/to/file:LINE`
   - DLS エントリ: `DLS-XXX`
   - コミット: `<sha>`（7桁短縮可）
   - 外部 URL: `[タイトル](URL)`

---

## いつ使うか

- `/dls-commit` の Phase 1.7（コミット直後）— **手順 A** で完了タスクを削除
- `/dls-clean` の Phase 2 — **手順 B** で DRY 違反を検出
- `/dls-continue` の起動直後 — **手順 C** で next.md ↔ todo.md の整合を取る（DLS-123）
- 手動実行（todo.md が肥大化したと感じたとき）

---

## 推奨フォーマット

```markdown
# Todo

## Active

- [ ] **タスク名** (関連: DLS-XXX, path/to/file:42)
  - 必要情報: 補足のみ（詳細はリンク先参照）
  - 残作業: ...

## Reference Links

（active タスクで参照する外部リンクのみ。完了タスクの履歴は載せない）
```

`Active` セクション以外（例: `Plan` / `Review` / `Done`）を使ってよいが、**完了済みの項目は次回 `/dls-commit` で削除される前提**で書く。

---

## 手順 A: 完了タスクの整理（`/dls-commit` から呼ばれる）

### Step 1: 直前のコミット内容を取得

```
git show --stat HEAD       # 変更ファイル一覧
git log -1 --pretty=%B HEAD  # コミットメッセージ本文
```

### Step 2: todo.md の完了候補をスキャン

`tasks/todo.md` を読み、以下を完了候補として抽出する:
- `- [x]` でチェック済みの項目
- `Active` セクション以外（`Done` / `Review` / `Plan` 等）に置かれた項目で、内容がコミット対象ファイルや DLS-XXX と意味的に一致するもの
- 直前コミットの変更内容と意味的に対応する `Active` 項目

### Step 3: 永続化先の確認

各候補について以下を判定:

| 候補の内容 | 永続化先 | 確認方法 |
|---|---|---|
| 「実装した」「変更した」 | コミットメッセージ + diff | `git log` / `git show HEAD` |
| 「判断した」「方針を決めた」「棄却した」 | DLS エントリ | `.claude/.dls/active.md` |
| 「外部仕様を参照した」 | sources / raw/ | `.claude/.dls/raw/` |

**永続化されていなければ補完を促す:**
- 判断 → DLS エントリ作成 (`skills/01_generate_entry.md`)
- 変更内容 → コミットメッセージ amend or 次コミットに含める
- 補完なしに削除しない

### Step 4: ユーザー承認のうえ削除

候補リストと永続化状況を提示し、ユーザー承認を得てから todo.md の該当行を削除する。

**プロンプトテンプレート:**

```
todo.md の以下の項目は直前のコミット (<sha> <subject>) で完了したと判断しました。
削除してよいか確認してください。

【削除候補】
- [行番号 N] 「タスクA」 → コミット <sha> の <file> で実装済み
- [行番号 M] 「タスクB」 → DLS-XXX で判断ログ化済み

【未永続化】
- [行番号 K] 「タスクC」 → 永続化先が見つかりません。次のいずれかを選んでください:
  (a) DLS エントリを作成して削除
  (b) このコミットを amend してメッセージ追記
  (c) 削除せず todo.md に残す
```

---

## 手順 B: DRY 違反検出（`/dls-clean` から呼ばれる）

### Step 1: todo.md の各タスク本文をスキャン

`tasks/todo.md` を読み、各 `Active` タスクの本文（`必要情報`/`残作業`/補足）を抽出する。

### Step 2: マスターとの重複を検出

各記述について以下を確認:

1. **DLS エントリとの重複**
   - 記述内容が `.claude/.dls/active.md` のいずれかのエントリの `what`/`why`/`rejected_alternatives` と意味的に一致しないか
   - 一致するなら `DLS-XXX` リンクへの置換を提案する

2. **コードとの重複**
   - 「ファイル X で関数 Y は…する」のように、コードを読めば自明な事実が書かれていないか
   - 書かれていれば `path/to/file:LINE` への置換を提案する

3. **外部ドキュメントとの重複**
   - 仕様書・URL の内容を貼り付けていないか
   - 貼り付けていれば `[タイトル](URL)` への置換を提案する

### Step 3: ユーザー承認のうえ置換

違反箇所と提案リンクを提示し、ユーザー承認を得てから置換する。

**プロンプトテンプレート:**

```
todo.md に以下の DRY 違反を検出しました。リンク化してよいか確認してください。

【違反一覧】
- [行番号 N] 「<引用>」 → DLS-XXX に同内容あり。リンク化を推奨
- [行番号 M] 「<引用>」 → init.py:265-286 と重複。`init.py:265` リンクに置換を推奨
```

---

## 手順 C: next.md ↔ todo.md 整合（`/dls-continue` から呼ばれる）

DLS-123: タスク本体は `tasks/todo.md` の `Active` セクションに一元化する。
`tasks/next.md` の「次のアクション」セクションは todo.md への参照リンクのみで、
タスク文言を直接書かない。`/dls-continue` 起動時に旧形式が残っていれば移送する。

### Step 1: next.md の「次のアクション」を解析

`tasks/next.md` を読み、「## 次のアクション」セクションの本文を抽出する。

| 状態 | 判定 | 動作 |
|---|---|---|
| 「→ `tasks/todo.md` の Active セクションを参照」のみ | 新形式（DLS-123 準拠） | 何もしない |
| タスク文言が直接書かれている（`- [ ]` / 番号付きリスト等） | 旧形式 | Step 2 へ |
| セクション自体が空・存在しない | OK | 何もしない |

### Step 2: 旧形式タスクを todo.md に移送

旧形式のタスク文言を抽出し、以下のフォーマットで `tasks/todo.md` の `Active` セクションに転記する:

```markdown
- [ ] **<タスク名>** （next.md から移送、出典セッション: <next.md の作成日時>）
  - <next.md にあった補足情報>
```

転記後:
1. 重複検査: 同じタスクが既に todo.md の Active にある場合は転記しない
2. next.md の「次のアクション」セクションを以下に置換:
   ```markdown
   ## 次のアクション

   → `tasks/todo.md` の `Active` セクションを参照（DLS-123: タスク本体は todo.md に一元化）
   ```

### Step 3: ユーザーに報告

```
next.md の旧形式タスク N 件を todo.md の Active に移送しました。
- 移送タスク 1: ...
- 移送タスク 2: ...
next.md の「次のアクション」を todo.md 参照のみに置換しました。
これから todo.md の Active 最上位タスクに着手します。
```

### Step 4: 着手

`/dls-continue` の通常フローに戻り、todo.md の Active 最上位タスクから作業を開始する。

---

## 注意事項

- **自動削除はしない**。手順 A・B どちらも提案＋ユーザー承認が必須
- **手順 C の移送は自動化してよい**（情報損失なし、todo.md に集約するだけ）
- **完了候補が見つからなくても OK**。todo.md が空・Active のみ・全項目が永続化済みなら何もしない
- **`tasks/todo.md` / `tasks/next.md` 不在時はスキップする**（エラーにしない。`init.py` が初回作成する）
- **永続化されていない情報を消さない**。「永続化先がない」なら DLS エントリ作成 / コミット amend を促してから削除する
- DLS と todo.md の境界が曖昧な情報（手続き的知識・環境要件）は `tasks/lessons.md` への移動を提案する
