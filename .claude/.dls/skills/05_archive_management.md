# Skill 05 — アーカイブ管理

active.md が肥大化したとき、または Phase 終了 / コミット集約イベント時に実行する。
エントリを整理・統合し、active.md を **目安 30 件** 前後に保つ（DLS-144 軟上限化）。
超過自体は禁則ではなく、減衰候補レビューによって判断履歴の活性度を調整する。

---

## いつ使うか

- active.md が目安 30 件を超え、Phase 終了 or コミット集約イベントが起きたとき（DLS-144）
- supersedes されたエントリが残っているとき
- 関連エントリをまとめて整理したいとき
- プロジェクト完了後のクリーンアップ

---

## 手順

### Step 1: 状況を把握する

**プロンプトテンプレート:**

```
.claude/.dls/active.md の現状を分析して以下を報告してください。

1. 総エントリ数
2. supersedes が記録されているが archive に未移動のエントリ（即移動対象）
3. 統合候補のエントリグループ（同じ機能・同じ where に関連するエントリ群）
4. confidence: low の assumption を持つエントリ（要確認リスト）
5. affects / depends_on が孤立しているエントリ（参照先が存在しないもの）
6. date が長期間前（プロジェクトの活動頻度に応じて判断）で、他エントリから参照されていないエントリ（減衰候補）
```

### Step 2: supersedes 済みエントリを archive に移動する

```
【手順】
1. active.md で supersedes が記録されているエントリを全て特定する
2. 該当エントリを archive.md の末尾にコピーする
3. archive.md への移動日をエントリ末尾に追記する:
   - **archived**: YYYY-MM-DD（supersedes by DLS-XXX）
4. active.md から該当エントリを削除する
```

**プロンプトテンプレート:**

```
.claude/.dls/active.md にある supersedes 済みのエントリを .claude/.dls/archive.md に移動する
手順を示してください。

移動するエントリのリスト:
（Step 1 で特定したエントリ番号）
```

### Step 2.5: 全件分類による減衰候補レビュー

active.md が目安件数を超える場合、**全エントリを未分類で残さない**。各エントリについて date、
incoming の depends_on / affects / supersedes、`where` に対応する git 更新履歴を確認し、次のいずれかに分類する:

- 即時archive候補: 全面的に supersede 済み
- 減衰archive候補: 長期間未更新 + 他エントリから未参照 + `where` 非活性
- 保持: 現在のコード・運用・依存関係のいずれかが有効（理由を記録）
- 追加証拠収集: 判定に必要な情報が不足（このレビュー内で行う調査コマンドと判定条件を記録）

件数が多ければバッチに分けてよいが、全件の分類表を出し切るまで「将来個別精査する」とだけ報告して終了してはならない。
archive候補の移動は従来どおりユーザー承認後に行う。

### Step 3: 関連エントリを統合する（任意）

複数のエントリが同じ判断を細かく分割して記録している場合、統合できる。

**統合の基準:**
- 同じ `where`（影響範囲）を持つ関連エントリ
- `depends_on` / `affects` で密接につながっているエントリ群
- 個別では意味が薄く、まとめると判断の全体像が見えるもの

**プロンプトテンプレート:**

```
以下のエントリ群を1つのエントリに統合してください。

【統合対象】
DLS-XXX, DLS-XXX, DLS-XXX

【統合ルール】
1. 新しいエントリ番号は現在の最大番号+1を使う
2. 統合元の what をすべて網羅した what を書く
3. why は統合元の最も重要なビジネス動機を残す
4. supersedes に統合元のエントリ番号をすべて列挙する
5. sources は統合元のすべての sources を引き継ぐ
6. rejected_alternatives は統合元のすべてを引き継ぐ
```

### Step 4: active.md のエントリ数カウントを更新する

active.md の冒頭コメント `エントリ数: N（目安 30）` を現在の実数に更新する。
Phase 集約期で超過している場合はその旨を括弧書きで残す（例: `35（目安 30、Phase 4a 集約期）`）。

---

## アーカイブ済みエントリの復元

稀なケースだが、archive.md のエントリを参照して判断を再検討する場合:

```
【手順】
新しいエントリを作成し、以下を明記する:
- depends_on または supersedes に archive.md の該当エントリ番号を記載
- why に「過去に棄却したが、XXXの状況変化により再検討」と明記
archive.md のエントリは削除しない。
```

---

## プロジェクト完了時のクリーンアップ

**プロンプトテンプレート:**

```
プロジェクト完了に伴い .claude/.dls/active.md を整理してください。

1. active.md の全エントリを pattern 候補として分析する:
   - 他プロジェクトでも適用できる汎用的な判断パターンを特定する
   - パターン化できる場合: domain / phase / pattern / caveat を抽出する
   
2. プロジェクト固有の判断を archive.md に移動する

3. 汎用パターンのリストを出力する（patterns.md への記録用）
```

---

## 注意事項

- archive.md に移動したエントリは**絶対に削除しない**
- 統合は不可逆操作に近い。統合前に active.md をバックアップする
- 統合よりも archive 移動を優先する（統合は情報損失のリスクがある）
